# Техническое задание: onecadmin v1.0

## 1. Назначение

Разработать приложение `onecadmin` для администрирования кластеров серверов 1С:Предприятия через уже запущенные службы RAS и утилиту `rac.exe`.

Приложение должно предоставлять:

- полноэкранный терминальный интерфейс TUI;
- отдельные CLI-команды, выполняемые без запуска TUI;
- поиск информационных баз по всем настроенным кластерам;
- просмотр, фильтрацию, сортировку и завершение сеансов;
- просмотр, фильтрацию, сортировку и разрыв соединений;
- управление списком подключений к RAS;
- форматы вывода `table`, `json`, `csv`.

## 2. Технические ограничения

| Параметр | Требование |
|---|---|
| Язык | Rust |
| ОС исполнения | Windows 10/11 x64 |
| Версия платформы 1С | 8.3.20 и новее |
| Интерфейс | TUI и CLI |
| Поставка | Один portable-файл `onecadmin.exe` |
| RAS | Уже запущен, приложение его не запускает |
| RAC | Не включается в EXE, ищется среди установленных платформ |
| Язык TUI и сообщений | Русский |
| Команды и поля CLI | Английский |
| Конфигурация | YAML |
| Хранение паролей | В открытом виде в YAML |

Одна настроенная служба RAS всегда соответствует одному кластеру 1С. Если `rac cluster list` возвращает ноль или более одного кластера, подключение считается некорректным.

## 3. Терминология

| Термин | Значение |
|---|---|
| RAS address | Адрес сервера администрирования, например `RV-DEV-1C01:1545` |
| Cluster alias | Уникальное пользовательское имя подключения, например `dev` |
| Cluster | Единственный кластер, возвращенный настроенным RAS |
| Infobase | Информационная база 1С |
| Cluster credentials | Учетные данные администратора кластера |
| Infobase credentials | Учетные данные администратора информационной базы |
| OS authentication | Аутентификация текущей учетной записью Windows |
| Password authentication | Аутентификация логином и паролем 1С |

Адрес RAS не используется для формирования клиентской строки подключения к информационной базе. Значения `host` и `port` должны браться из результата `rac cluster list`.

## 4. Режимы запуска

Запуск без команды должен открывать TUI:

```powershell
onecadmin
```

CLI-команды не должны инициализировать или загружать TUI:

```powershell
onecadmin session list --infobase zup_corp
```

Вызовы `--help`, `--version` и любые подкоманды также не должны запускать TUI.

## 5. Конфигурация

Путь по умолчанию:

```text
%APPDATA%\onecadmin\config.yaml
```

Приоритет выбора файла:

1. Глобальный аргумент `--config`.
2. Переменная окружения `ONECADMIN_CONFIG`.
3. Путь по умолчанию.

Пример структуры:

```yaml
schema_version: 1

settings:
  timeout_seconds: 30
  rac_path: null
  log_level: INFO

clusters:
  dev:
    ras:
      host: RV-DEV-1C01
      port: 1545

    discovered_cluster:
      uuid: 00000000-0000-0000-0000-000000000000
      name: Development cluster
      host: RV-DEV-1C01
      port: 1541

    rac:
      path: null
      version: auto

    cluster_auth:
      mode: password
      user: cluster_admin
      password: plain-text-password

    infobase_auth:
      default:
        mode: password
        user: infobase_admin
        password: plain-text-password

      overrides:
        - infobase: zup_corp
          infobase_uuid: null
          mode: os
          user: domain_infobase_user
          os_user: DOMAIN\username
```

Требования к конфигурации:

- Alias является ключом в секции `clusters`.
- Alias уникален без учета регистра.
- Допустимые символы alias: латинские буквы, цифры, `.`, `_`, `-`, `:`.
- В password-режиме поля `user` и `password` обязательны.
- В OS-режиме пароль отсутствует.
- В none-режиме логин и пароль не требуются
- `os_user` задает ожидаемую текущую учетную запись Windows.
- Переопределение учетных данных базы выбирается сначала по UUID, затем по точному имени без учета регистра.
- Если переопределение отсутствует, используются общие учетные данные базы.
- Переопределения не должны использовать маски.
- YAML должен проверяться типизированной схемой.
- Неизвестные или некорректные поля должны приводить к понятной ошибке конфигурации.
- Запись файла выполняется атомарно с файловой блокировкой.
- При записи необходимо по возможности сохранять комментарии и порядок YAML.
- При создании файла приложению следует ограничить ACL текущим пользователем Windows.
- В документации должно быть явно указано, что пароли хранятся открыто.

## 6. Управление подключениями

В CLI поддерживаются только операции добавления и удаления.

Добавление password-подключения:

```powershell
onecadmin cluster add `
  --name dev `
  --ras RV-DEV-1C01:1545 `
  --auth password `
  --user username `
  --password password
```

`--pwd` должен быть алиасом `--password`.

Добавление с общей учетной записью информационных баз:

```powershell
onecadmin cluster add `
  --name dev `
  --ras RV-DEV-1C01:1545 `
  --auth password `
  --user cluster_admin `
  --password cluster_password `
  --infobase-auth password `
  --infobase-user infobase_admin `
  --infobase-password infobase_password
```

Добавление с OS-аутентификацией:

```powershell
onecadmin cluster add `
  --name dev `
  --ras RV-DEV-1C01:1545 `
  --auth os `
  --user cluster_admin `
  --os-user 'DOMAIN\username'
```

Пароль должен передаваться аргументом. Интерактивный скрытый запрос пароля не требуется.

При выполнении `cluster add` приложение должно:

1. Проверить уникальность alias.
2. Найти совместимый `rac.exe`.
3. Подключиться к RAS.
4. Выполнить `cluster list`.
5. Убедиться, что найден ровно один кластер.
6. Проверить кластерную аутентификацию запросом данных кластера или списка баз.
7. Получить UUID, имя, host и port кластера.
8. Сохранить запись только после успешной проверки.

Офлайн-добавление и опция `--no-validate` не поддерживаются.

Удаление:

```powershell
onecadmin cluster remove --name dev
onecadmin cluster remove --name dev --force
```

Без `--force` требуется подтверждение. Команды `cluster update`, `cluster test` и отдельная CLI-команда просмотра подключений в первой версии не реализуются.

Изменение общих учетных данных выполняется вручную в YAML или удалением и повторным добавлением подключения. Переопределения учетных данных информационных баз управляются в TUI или вручную в YAML.

## 7. Поиск информационных баз

Основная команда:

```powershell
onecadmin infobase search zup_corp
onecadmin infobase search 'zup_corp%'
onecadmin infobase search 'zup_corp%' --cluster 'prod%'
```

Top-level команда `onecadmin search` не реализуется.

Если `--cluster` не указан, поиск выполняется во всех настроенных кластерах.

Поиск выполняется по имени информационной базы:

- Без `%` и `_` используется точное совпадение без учета регистра.
- `%` соответствует произвольной последовательности символов.
- `_` соответствует одному символу.
- `\%`, `\_` и `\\` используются для экранирования.
- Нечеткий поиск и автоматический поиск по подстроке не выполняются.

Результат должен содержать:

```text
cluster
cluster_name
ras_address
infobase
infobase_uuid
connection_string
```

Строка подключения всегда включает порт кластера:

```text
Srvr="RV-MNG-DB01:1541";Ref="WorkFlow_TEST";
```

Даже стандартный порт `1541` не должен опускаться. Если база найдена в нескольких кластерах, выводится отдельная строка для каждого кластера.

## 8. Работа с сеансами

Получение сеансов:

```powershell
onecadmin session list
onecadmin session list --infobase zup_corp
onecadmin session list --infobase 'zup_corp%'
onecadmin session list --cluster dev --infobase zup_corp
onecadmin session list --query 'DOMAIN\ivanov'
onecadmin session list --query 'PC-123%'
onecadmin session list --top 10 --sort cpu_time_total:desc
```

Если кластер не указан, поиск выполняется по всем настроенным кластерам.

Если база указана, но кластер не указан, приложение должно:

1. Получить список баз каждого кластера.
2. Найти базы, подходящие под имя или маску.
3. Получить сеансы кластеров.
4. Сопоставить UUID базы с ее именем.
5. Оставить сеансы подходящих баз.
6. Объединить результаты всех кластеров.

Общая строка `--query` ищет по двум полям с логикой OR:

```text
user_name
host
```

Дополнительные селекторы:

```text
--id <session UUID>
--number <session number>
--user <name or mask>
--host <name or mask>
--app <app_id or mask>
```

Завершение сеансов:

```powershell
onecadmin session kill --id <uuid>
onecadmin session kill --number 123 --cluster dev
onecadmin session kill --user 'test%' --infobase zup_corp
onecadmin session kill --user 'test%' --infobase zup_corp --force
onecadmin session kill --id <uuid> --message "Сеанс завершен администратором"
```

Если `--message` отсутствует, используется:

```text
Сеанс принудительно завершен администратором через onecadmin
```

Перед массовым завершением приложение должно показать выбранные сеансы и их количество.

Без `--force` требуется подтверждение. В неинтерактивном окружении отсутствие `--force` является ошибкой безопасности.

Массовое завершение без селектора запрещено даже с `--force`. Наличия только `--cluster` недостаточно. Требуется хотя бы один из параметров:

```text
--id
--number
--infobase
--query
--user
--host
--app
--filter
```

Операция выполняется по UUID сеансов из одного зафиксированного снимка данных. Ошибка завершения одного сеанса не должна останавливать обработку остальных.

## 9. Работа с соединениями

Получение соединений:

```powershell
onecadmin connection list
onecadmin connection list --cluster dev
onecadmin connection list --infobase 'zup%'
onecadmin connection list --query 'APP-SERVER%'
onecadmin connection list --sort connected_at:desc
```

Общая строка `--query` проверяет с логикой OR:

```text
host
application
```

Дополнительные селекторы:

```text
--id <connection UUID>
--number <conn_id>
--host <name or mask>
--application <name or mask>
--process <process UUID>
```

Разрыв соединений:

```powershell
onecadmin connection kill --id <uuid>
onecadmin connection kill --number 154 --cluster dev
onecadmin connection kill --host 'APP-%' --infobase zup_corp
onecadmin connection kill --host 'APP-%' --force
```

Для `rac connection kill` приложение должно передавать UUID рабочего процесса и UUID соединения, полученные из одного снимка.

Для операции выбираются учетные данные соответствующей информационной базы. При отсутствии необходимых credentials должна возвращаться понятная ошибка без попытки использовать случайные или пустые значения.

Правила подтверждения, массовой обработки и запрета операции без фильтра аналогичны завершению сеансов.

## 10. Фильтрация

Поддерживаются именованные параметры и универсальный фильтр:

```powershell
onecadmin session list --filter cpu_time_total:gt:100000
onecadmin session list `
  --filter cpu_time_total:gt:100000 `
  --filter app_id:like:1CV8%
```

Формат:

```text
--filter field:operator:value
```

Строка разделяется только по первым двум символам `:`, поэтому значение может содержать двоеточия.

Операторы:

| Оператор | Назначение |
|---|---|
| `eq` | Равенство |
| `ne` | Неравенство |
| `like` | Сопоставление строки с `%` и `_` |
| `gt` | Больше |
| `ge` | Больше или равно |
| `lt` | Меньше |
| `le` | Меньше или равно |

Требования:

- Тип значения определяется схемой поля.
- `gt`, `ge`, `lt`, `le` доступны только для чисел и дат.
- `like` доступен только для строк.
- Строковые сравнения выполняются без учета регистра.
- Все повторяемые `--filter` объединяются через AND.
- Именованные фильтры также объединяются через AND.
- Внутри одного `--query` используется OR между предусмотренными для него полями.
- Невалидное поле, оператор или значение обнаруживается до сетевых запросов.
- Фильтрация выполняется приложением после получения данных RAC для единообразия между версиями платформы.

## 11. Сортировка и Top

Синтаксис сортировки:

```powershell
--sort field:asc
--sort field:desc
```

Параметр может повторяться:

```powershell
onecadmin session list `
  --sort cpu_time_total:desc `
  --sort started_at:asc
```

Требования:

- Используются только точные канонические имена полей.
- Короткий alias `cpu_time` не поддерживается.
- Для суммарного CPU используется `cpu_time_total`.
- Сортировка типизированная: числа как числа, даты как даты.
- Пустые значения всегда располагаются после заполненных.
- Несколько сортировок применяются в указанном порядке.
- Сортировка стабильная.
- Результаты всех кластеров сначала объединяются, затем глобально сортируются.
- `--top N` применяется после глобальной сортировки.
- `N` должно быть положительным целым числом.
- Без `--top` возвращаются все строки.

Сортировка по умолчанию для сеансов:

```text
cluster:asc, infobase:asc, session_id:asc
```

Сортировка по умолчанию для соединений:

```text
cluster:asc, infobase:asc, conn_id:asc
```

## 12. Канонические поля

```text

last-active-at -> last_active_at
user-name -> user_name
```

Короткие или неоднозначные aliases не вводятся.

Приложение добавляет поля источника:


Единицы измерения каждого числового поля должны быть зафиксированы в реестре полей на основании документации и проверенных ответов RAC. Форматтер не должен предполагать единицы для неизвестных полей.

```text
user_name

app_id

last_active_at

```

Колонки соединений по умолчанию:

```text
cluster

conn_id
host
application
connected_at
session_number

```

Колонки поиска баз по умолчанию:

```text
cluster

infobase
infobase_uuid

```

Пользователь может задать порядок и состав:

```powershell
onecadmin session list --columns cluster,infobase,user_name,cpu_time_total
onecadmin session list --columns "*"
```

Если `--columns` не указан, используется набор по умолчанию. Это правило применяется к `table`, `json` и `csv`.

Неизвестная или неприменимая колонка должна приводить к ошибке валидации.

## 14. Форматы вывода

```powershell
onecadmin session list --format table
onecadmin session list --format json
onecadmin session list --format csv
```

`table` используется по умолчанию.

Требования к `table`:

- Длительности и размеры форматируются в удобном для человека виде.
- Даты отображаются в локальном времени.
- Таблица корректно адаптируется к ширине терминала.
- Длинные значения допускают усечение только визуально, без изменения данных.
- Цвет отключается при `--no-color`.

Требования к `json` и `csv`:

- Числа остаются числами или исходными числовыми значениями RAC.
- UUID сериализуются полностью.
- Даты сериализуются в ISO 8601.
- JSON использует UTF-8 и `ensure_ascii=false`.
- CSV соответствует RFC 4180 и использует UTF-8.
- Декоративный текст и progress-индикаторы не попадают в stdout.

Форма JSON:

```json
{
  "data": [],
  "errors": [],
  "meta": {
    "matched": 0,
    "returned": 0,
    "partial": false
  }
}
```

Для таблицы и CSV ошибки отдельных кластеров выводятся в stderr.

## 15. Частичные ошибки

Запросы ко всем выбранным кластерам выполняются независимо.

Если часть кластеров недоступна:

- данные доступных кластеров должны быть выведены;
- ошибки должны содержать alias, RAS address, код и сообщение;
- команда завершается кодом частичного успеха;
- ошибка одного кластера не должна отменять остальные запросы.

Если не ответил ни один кластер, команда завершается ошибкой без ложного успешного результата.

Пустой корректный результат поиска или списка не является ошибкой.

## 16. Коды завершения

| Код | Значение |
|---:|---|
| `0` | Успех, включая пустой результат чтения |
| `1` | Необработанная внутренняя ошибка |
| `2` | Ошибка аргументов, конфигурации, фильтра или колонки |
| `3` | `rac.exe` не найден или нет совместимой версии |
| `4` | Операция завершилась ошибкой для всех целей |
| `5` | Частичный успех |
| `6` | Операция отменена или требуется подтверждение |
| `7` | Разрушающая операция не нашла объектов |
| `130` | Прерывание пользователем |

## 17. TUI

TUI должен быть реализован как полноэкранное приложение с управлением клавиатурой.

Обязательные разделы:

| Раздел | Возможности |
|---|---|
| Кластеры | Просмотр, добавление, удаление подключений |
| Credentials | Просмотр, добавление и удаление overrides информационных баз |
| Информационные базы | Глобальный поиск и строки подключения |
| Сеансы | Таблица, фильтры, сортировка, детали, завершение |
| Соединения | Таблица, фильтры, сортировка, детали, разрыв |
| Диагностика | Ошибки текущих запросов и сведения о выбранном RAC |

Требования к TUI:

- Все сетевые операции выполняются асинхронно.
- Интерфейс не блокируется во время работы RAC.
- Должна присутствовать ручная команда обновления, например `F5`.
- Автообновление по умолчанию выключено.
- Предустановленные интервалы: 5, 10, 30 и 60 секунд.
- Пользовательский интервал не может быть меньше 2 секунд.
- Новый refresh не запускается, пока не завершен предыдущий.
- Фильтры, сортировка и колонки сохраняются между обновлениями текущего экрана.
- Выделение сохраняется по UUID, если объект еще существует.
- Таблицы должны поддерживать большие наборы строк без создания отдельного виджета на каждую ячейку.
- Для завершения и разрыва должна поддерживаться множественная выборка.
- Перед опасным действием показываются объекты и запрашивается подтверждение.
- Детальный экран показывает все известные поля объекта.
- Русские подписи интерфейса не изменяют английские канонические имена полей.

## 18. Поиск rac.exe

Поддерживаются установленные версии 1С 8.3.20 и новее.

Источники поиска:

```text
явный --rac-path
ONECADMIN_RAC_PATH
per-cluster rac.path/rac.version
глобальный settings.rac_path
PATH
реестр Windows
%ProgramFiles%\1cv8\*\bin\rac.exe
%ProgramFiles(x86)%\1cv8\*\bin\rac.exe
```

Требования:

- Каждый найденный файл проверяется через `rac --version`.
- Версии ниже 8.3.20 игнорируются.
- Дубликаты путей удаляются.
- В auto-режиме кандидаты проверяются от новой версии к старой.
- Совместимая версия определяется отдельно для каждого RAS.
- При протокольной несовместимости выполняется fallback на следующую версию.
- При DNS-ошибке, timeout или отказе подключения бессмысленный перебор всех версий не выполняется.
- Явно заданный путь считается обязательным и не заменяется автоматически.
- Выбранный путь кэшируется на время процесса.
- `ras.exe` не ищется и не запускается.

## 19. Вызов и разбор RAC

RAC должен вызываться через `asyncio.create_subprocess_exec` или эквивалентный безопасный API.

Запрещено:

- формировать shell-команду одной строкой;
- использовать `shell=True`;
- передавать пользовательские значения через интерпретацию PowerShell или CMD;
- записывать пароли в лог.

Требования к исполнителю RAC:

- Каждый аргумент передается отдельным элементом списка.
- Timeout по умолчанию составляет 30 секунд.
- Timeout настраивается через YAML и `--timeout`.
- При timeout процесс завершается.
- Отмена операции TUI завершает соответствующий дочерний процесс.
- Между разными кластерами не устанавливается программный лимит параллельности.
- Запросы ко всем выбранным кластерам запускаются одновременно.
- Внутри одного кластера зависимые команды выполняются последовательно.

Парсер должен:

- разделять записи по пустым строкам;
- разделять ключ и значение только по первому разделителю `:`;
- поддерживать пустые значения и двоеточия внутри значений;
- обрабатывать CRLF и LF;
- поддерживать UTF-8, системную ANSI-кодировку и OEM-кодировку Windows;
- не смешивать stderr с данными stdout;
- сохранять неизвестные поля;
- иметь тестовые fixtures минимум для RAC 8.3.20 и актуальной версии.

## 20. Аутентификация

Поддерживаются два режима:

| Режим | Поведение |
|---|---|
| `password` | В RAC передаются имя администратора и пароль |
| `os` | Используется текущая учетная запись Windows, пароль не передается |

В OS-режиме:

- Приложение не выполняет impersonation другой учетной записи.
- `os_user` используется для проверки ожидаемой Windows identity.
- Должна поддерживаться кластерная и инфобазная OS-аутентификация.
- При неподдерживаемом платформой сценарии возвращается явная ошибка `unsupported_auth`.
- Запрещено незаметно переходить на пустой пароль или другой способ аутентификации.

Перед выпуском обязательны интеграционные тесты OS-аутентификации на 1С 8.3.20 и одной актуальной версии.

## 21. Логи и аудит

Технический лог:

```text
%LOCALAPPDATA%\onecadmin\logs\onecadmin.log
```

Аудит:

```text
%LOCALAPPDATA%\onecadmin\logs\audit.jsonl
```

Технический лог должен быть ротационным. Рекомендуемое ограничение: пять файлов по 10 MiB.

Пароли должны удаляться из:

- командных строк в логах;
- сообщений исключений;
- Debug-вывода;
- JSON ошибок;
- аудита.

Аудит фиксирует:

```text
UTC timestamp
Windows user
action
cluster alias
cluster UUID
infobase name/UUID
session или connection UUID
numeric ID
message/reason
result
error code
```

Аудируются завершение сеансов, разрыв соединений, добавление и удаление кластеров, изменение overrides через TUI.

Передача пароля в аргументе CLI и дочерней командной строке RAC может быть видна в истории PowerShell и списке процессов. Это принятое ограничение должно быть явно отражено в документации.

```text
|   |   |-- credentials.rs

```

В первой версии используется один Cargo-пакет с библиотечной целью и одним бинарным файлом. Разделение на workspace и несколько внутренних crates не требуется. `main.rs` содержит только разбор режима запуска, создание runtime, вызов bootstrap и преобразование результата в код завершения. Основная логика располагается в библиотечной части и доступна тестам без запуска процесса.

Направление зависимостей:

```text
CLI ----\
         > application ---> domain
TUI ----/         |
                  `-- ports <--- infrastructure

bootstrap связывает реализации портов и application services
```

Требования к границам слоев:

- `domain` содержит модели, типы значений, реестр полей, маски, фильтрацию, сортировку и предметные инварианты. Он не зависит от CLI, TUI, YAML, файловой системы, Windows API и формата вывода RAC.
- `application` содержит сценарии использования и порты внешних систем. Он зависит от `domain`, но не от конкретных реализаций RAC, конфигурации и интерфейса пользователя.
- `infrastructure` реализует порты для RAC, YAML, файловой системы, Windows, логов и аудита.
- `cli` и `tui` преобразуют пользовательский ввод в типизированные запросы application services и отображают результат. Они не вызывают RAC и не изменяют YAML напрямую.
- `bootstrap` является единственным composition root. Ручное создание инфраструктурных зависимостей внутри сервисов запрещено.
- Traits вводятся на границах ввода-вывода. Чистые компоненты парсинга, фильтрации и сортировки реализуются обычными структурами и функциями.

Основные классы и интерфейсы:

В терминах Rust классы представлены структурами и перечислениями, интерфейсы представлены traits.

| Компонент | Вид | Ответственность |
|---|---|---|

Основные application services:

| Сервис | Операции |
|---|---|
| `ClusterService` | Просмотр для TUI, проверка и добавление подключения, подготовка и удаление подключения |
| `CredentialService` | Просмотр, добавление и удаление overrides информационных баз |
| `InfobaseService` | Глобальный поиск баз и формирование строк подключения |
| `SessionService` | Получение сеансов, подготовка и выполнение завершения |
| `ConnectionService` | Получение соединений, подготовка и выполнение разрыва |
| `DiagnosticsService` | Ошибки последних запросов, выбранный путь и версия RAC, причины fallback |
| `QueryEngine` | Общая типизированная фильтрация, стабильная сортировка, top и проекция |

Адаптер RAC состоит из следующих компонентов:

| Компонент | Ответственность |
|---|---|
| `RacLocator` | Поиск кандидатов во всех предусмотренных источниках и удаление дубликатов |
| `RacVersionProbe` | Безопасный вызов `rac --version` и проверка минимальной версии |
| `RacCompatibilityResolver` | Выбор версии для конкретного RAS, классификация ошибок и разрешенный fallback |
| `RacProcessRunner` | Запуск без shell, timeout, отмена и обязательное завершение дочернего процесса |
| `RacOutputDecoder` | Независимое декодирование stdout и stderr из UTF-8, cp1251 или cp866 |
| `RacRecordParser` | Разделение записей и пар `key: value` с сохранением неизвестных полей |
| `RacNormalizer` | Преобразование имен и значений RAC в канонические типизированные записи |
| `RacArgumentBuilder` | Формирование argv и единственная точка раскрытия пароля для дочернего процесса |

`ConfigRepository` хранит два представления конфигурации: неизменяемый типизированный `ConfigSnapshot` для чтения и lossless `ConfigDocument` для изменения. Операция изменения захватывает межпроцессную блокировку, повторно читает и строго проверяет актуальный файл, точечно изменяет CST, повторно проверяет результат, записывает временный файл в том же каталоге, сбрасывает данные на диск, применяет требуемый ACL и выполняет атомарную замену. При ошибке исходный файл должен остаться неизменным.

Общий конвейер операций чтения:

1. Разобрать и полностью проверить поля, фильтры, сортировку, top и колонки до сетевых запросов.
2. Определить выбранные кластеры.
3. Запустить обработку кластеров одновременно без общего программного лимита.
4. Выполнить зависимые команды внутри одного кластера последовательно.
5. Декодировать, разобрать, нормализовать и дополнить записи контекстом источника.
6. Объединить результаты в детерминированном порядке, не зависящем от времени завершения процессов.
7. Применить фильтры и вычислить `matched`.
8. Выполнить стабильную глобальную сортировку, затем применить top и вычислить `returned`.
9. Применить проекцию колонок и вернуть `QueryOutcome` вместе с ошибками отдельных кластеров.

Разрушающие операции выполняются в две фазы:

1. Application service проверяет наличие предметного селектора и получает один снимок данных.
2. По снимку создается неизменяемый `SessionKillPlan` или `ConnectionKillPlan` с точными UUID и необходимым контекстом.
3. CLI или TUI показывает объекты и получает подтверждение либо признак `--force`.
4. Application service выполняет только объекты из плана без повторного поиска и продолжает работу после ошибки отдельного объекта.
5. Результаты каждого действия записываются в аудит и агрегируются в общий результат и код завершения.

Проверка запрета массовой операции без селектора находится в application service, а не только в CLI или TUI. Для идентификации объектов между кластерами используется составной ключ из UUID кластера и UUID объекта.

TUI реализуется как один цикл событий с централизованным состоянием. Фоновые задачи вызывают application services и возвращают результаты через канал. Каждому запросу назначается идентификатор; устаревшие результаты игнорируются. Для отмены используется отдельный cancellation token. Таблицы хранят строки и viewport, создавая представление только для видимых строк. Выбор хранится по составному ключу объекта. Инициализация терминала защищается guard-объектом, восстанавливающим состояние терминала при штатном выходе и ошибке.

Синхронный `main` сначала разбирает аргументы. `--help` и `--version` обрабатываются до создания Tokio runtime, загрузки конфигурации и инициализации TUI. После разбора приложение создает runtime и запускает только выбранный адаптер: TUI при отсутствии подкоманды или CLI dispatcher при наличии команды.

CLI и TUI должны использовать одни application services. Дублирование бизнес-логики между интерфейсами запрещено.

Конкретные версии прямых зависимостей задаются в `Cargo.toml`, а разрешенные версии фиксируются в `Cargo.lock`, который включается в репозиторий. Release-сборка выполняется с `--locked`. Для pre-1.0 зависимостей версия фиксируется точно и обновляется только после прохождения полного набора тестов. Неподдерживаемые `serde_yaml` и `serde_yml` использоваться не должны.

Требования к коду:

- Целевой triple: `x86_64-pc-windows-msvc`.
- Release-сборка должна статически связывать CRT и не требовать поставки сторонних DLL. Разрешены системные DLL Windows и найденный во время выполнения внешний `rac.exe`.
- В `Cargo.toml` должен быть задан `rust-version`. Проект проверяется как на указанной минимальной версии Rust, так и на актуальной stable-версии.
- Все публичные предметные значения должны быть типизированы. Alias, RAS endpoint, UUID разных сущностей, credentials и версия платформы не должны передаваться как взаимозаменяемые строки.
- Версия 1С разбирается собственным типом из четырех числовых компонентов. Использование SemVer для значения вида `8.3.20.XXXX` запрещено.
- Внешние ошибки представлены закрытыми типизированными категориями. Стабильный английский код ошибки отделяется от русского пользовательского сообщения.
- Преобразование application result в код завершения выполняется централизованно на границе CLI. Внутренние компоненты не вызывают `process::exit`.
- Ожидаемые ошибки ввода, RAC, YAML, файловой системы и Windows API не должны обрабатываться panic. `unwrap`, `expect` и индексирование с возможным panic запрещены для внешних данных.
- Все вызовы RAC выполняются через `tokio::process::Command`. Каждый аргумент передается отдельно; shell, PowerShell и CMD не используются.
- Каждый дочерний процесс имеет timeout и путь отмены. После timeout, отмены или Ctrl+C процесс завершается и ожидается его фактическое завершение.
- Потенциально блокирующие файловые и Windows-операции не выполняются в цикле событий TUI и переносятся в `spawn_blocking` или специализированный адаптер.
- Пароли хранятся в специальном типе без открытых реализаций `Debug` и `Display`. Раскрытие допускается только при чтении/записи конфигурации и построении argv RAC.
- Логирование выполняется структурированно. Перед записью применяются централизованная очистка секретов и безопасное представление командной строки.
- Неизвестные поля RAC сохраняются отдельно от известных полей и не могут перезаписывать поля контекста источника.
- `unsafe` допускается только в изолированном модуле `infrastructure/windows`, когда отсутствует безопасный API. Каждый unsafe-блок должен иметь комментарий с описанием проверенных условий безопасности.
- CLI, TUI и infrastructure не содержат собственных реализаций фильтрации, сортировки, выбора объектов или правил безопасности разрушающих операций.
- Исходный код, имена модулей, типов, методов, CLI-команд и канонических полей используются на английском языке. Русский язык используется в пользовательских сообщениях, TUI и справке.
- Код форматируется `rustfmt` и проходит `cargo clippy --all-targets --all-features -- -D warnings`.
- CI должен выполнять сборку с `--locked`, модульные и интеграционные тесты, `cargo-audit`, `cargo-deny` и расчет покрытия.
- Новая runtime-зависимость добавляется только после проверки лицензии, advisory, поддержки Windows и отсутствия обязательной внешней DLL.

## 24. Тестирование

Обязательные группы тестов:

- поиск всех вариантов расположения RAC;
- выбор версии и fallback;
- парсинг вывода RAC 8.3.20 и актуальной версии;
- парсинг русской и английской диагностики;
- обработка `cp866`, `cp1251` и UTF-8;
- точные совпадения и маски `%`, `_`;
- экранирование символов маски;
- типизированная фильтрация;
- многополевая сортировка и глобальный top;
- формирование `Srvr="host:port";Ref="name";`;
- валидация YAML;
- атомарное изменение конфигурации;
- редактирование overrides в TUI;
- запрет массовой операции без фильтра;
- подтверждение и `--force`;
- частичный успех;
- отсутствие паролей в логах;
- контракт JSON/CSV;
- smoke-тест собранного EXE на Windows 10 и Windows 11;
- интеграционные тесты с реальным RAS/RAC;
- интеграционные тесты password- и OS-аутентификации.

Рекомендуемое покрытие прикладного кода: не менее 60%. Критические компоненты фильтрации, выбора объектов и разрушающих операций должны иметь полное покрытие ветвей.

## 25. Критерии приемки

1. `onecadmin.exe` запускается на Windows 10+.
2. Запуск без аргументов открывает TUI.
3. CLI-команды не запускают и не инициализируют TUI.
4. `cluster add` проверяет RAS, единственность кластера и credentials до записи YAML.
5. Приложение самостоятельно находит совместимый RAC 8.3.20+.
6. Поиск `infobase search zup_corp` выполняет точное сопоставление по всем кластерам.
7. Поиск `infobase search 'zup_corp%'` поддерживает маску.
8. Строка подключения всегда содержит `host:port`.
9. `session list --infobase zup_corp` ищет базу во всех кластерах.
10. `session list --query ...` ищет без обязательного указания базы.
11. `--sort cpu_time_total:desc --top 10` применяется глобально после объединения результатов.
12. Ключ `cpu_time` отклоняется как неизвестное поле.
13. `connection list` поддерживает те же правила области, фильтрации и сортировки.
14. Завершение и разрыв поддерживают одиночные и массовые операции.
15. Массовая операция без фильтра запрещена даже с `--force`.
16. При недоступности части кластеров доступны результаты остальных и возвращается код `5`.
17. Table использует human-readable значения, JSON/CSV сохраняют исходные типизированные значения.
18. TUI поддерживает ручное и автоматическое обновление.
19. Пароли отсутствуют во всех логах и сообщениях ошибок.
20. Password- и OS-аутентификация подтверждены интеграционными тестами.

## 26. Вне первой версии

- Запуск, остановка или установка RAS.
- Работа с несколькими кластерами через один RAS.
- Поддержка 1С ниже 8.3.20.
- Linux и macOS.
- Web-интерфейс или desktop GUI.
- Создание, изменение и удаление информационных баз.
- Изменение параметров кластера.
- Администрирование процессов, серверов, блокировок и лицензий.
- OR-группы и произвольный язык логических выражений.
- Нечеткий или полнотекстовый поиск.
- Шифрование паролей.
- Windows Credential Manager.
- Инсталлятор и автоматическое обновление.
- Включение `rac.exe` или компонентов 1С в дистрибутив.
- Impersonation произвольной доменной учетной записи.

Открытых продуктовых вопросов нет. Обязательный технический риск до выпуска: практическая проверка OS-аутентификации информационных баз через RAC на минимальной и актуальной поддерживаемых версиях платформы.
